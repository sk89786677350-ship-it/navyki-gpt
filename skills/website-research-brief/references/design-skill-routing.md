# Маршрутизация дополнительных дизайн-навыков

Эти правила применяются вместе с основным процессом website-research-brief. Новый навык дополняет бриф, а не заменяет его.

## Taste Skill

- Рассматривай design-taste-frontend только для публичных сайтов, лендингов, портфолио и продуктовых страниц, когда нужен новый визуальный ход или пользователь выбрал этот способ работы.
- Не запускай его по умолчанию на каждом сайте. Не применяй для дашбордов и внутренних интерфейсов продукта.
- Сначала соблюдай полный проектный бриф, исследование и уже утвержденный фирменный стиль. Пользовательские решения и AGENTS.md выше рекомендаций стороннего навыка.
- Не выдумывай данные для полноты макета. Не считай минимальное число изображений, обязательный набор секций, анимацию или стиль Taste обязательными для проекта.
- Не ищи и не скачивай внешние изображения, не запускай инспектор браузера и не устанавливай зависимости без относящейся к задаче необходимости. Проверяй права на конкретное изображение и его атрибуцию.

## Навыки движения Emil Kowalski

- animate — выбирай для явно запрошенной конкретной анимации.
- review-animations — запускай для явного motion-review; его метаданные запрещают модельный авто-вызов. Не обещай автоматическую проверку после каждой правки.
- improve-animations — выбирай только для запроса на аудит анимаций всего репозитория. Он готовит план и не изменяет исходный код.
- Соблюдай системное уменьшение движения, назначение интерфейса и производительность. Авторские абсолютные ограничения оценивай в контексте, не выдавай их за универсальный норматив.
- Не запускай все три навыка в одном проекте без необходимости. Не делегируй подзадачи без запроса пользователя.

## Общее правило

Установленный навык сам по себе не разрешает заменять фирменный стиль, содержание, реальные продуктовые факты, проводить исследование, менять исходники, подключать сервисы или публиковать результат.
